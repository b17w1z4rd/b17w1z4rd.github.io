Shashank Patil · everything on the scoreboard that isn't crypto

Crypto has its own post. This is the rest of the board — the categories where the bug lives in code, in a protocol, in a packet capture, or, increasingly, in a language model's context window.

$ binary exploitation

Pwn is the category that teaches humility fastest, because the machine does not care what you meant — only what you wrote to memory. The bread-and-butter path is a stack buffer overflow: overrun a fixed buffer, overwrite the saved return address, and redirect execution to code of your choosing.

Modern mitigations make "code of your choosing" the hard part. With the stack non-executable (NX/DEP), you can't just drop shellcode and jump to it, so you reach for return-oriented programming — stitching together short instruction sequences (gadgets) that already exist in the binary, each ending in a ret, to build the behaviour you need out of the program's own bytes. Add ASLR and the first job becomes leaking an address to defeat the randomisation before the chain even runs.

The workflow settles into a rhythm: 

1. find the overflow, measure the exact offset to the return address
2. leak something — a libc address, a stack canary — to beat mitigations
3. build the ROP chain from available gadgets
4. redirect execution; land a shell or read the flag

Pwn is where you internalise that a program is just data the CPU has agreed to treat as instructions, and that the agreement is negotiable.

$ web

Web challenges are closest to the work most security engineers actually do, which is part of why I like them. A running sample of the bug classes:

  • JWT forgery. JSON Web Tokens are only as trustworthy as their verification. The classic failures: an alg: none token the server accepts unsigned, a weak HMAC secret you can brute-force offline, or the algorithm-confusion trick where a server expecting an asymmetric signature is fooled into verifying an attacker-forged token with the public key as a symmetric secret.
  • CSRF bypasses. Defeating the assumption that a request carrying the right cookie came from the right place — chaining weak same-site handling, sloppy token checks, or permissive CORS into a forged state-changing request.
  • XXE injection. An XML parser that resolves external entities will happily read local files or reach out to attacker-controlled URLs. It's an old bug that refuses to die because XML parsers ship dangerous by default.
  • LaTeX injection. My favourite, because it's a category error made concrete: someone forgot that a document compiler is a full programming language. Feed a server-side LaTeX renderer the right commands and you get arbitrary file read straight out of a PDF-generation endpoint.
Every one of these is the same shape as the RSA lesson: find where the implementer stopped checking. A token they trusted, a parser they left permissive, a compiler they mistook for a formatter.

$ forensics

Forensics is the category that quietly made me a better defender, and I didn't notice at the time. You're handed the artifact — a packet capture, a disk image, a suspicious file — and asked to reconstruct what happened.

  • pcap analysis. Following streams, reassembling transfers, and pulling the payload out of protocols that weren't trying very hard to hide it. This is the exact skill that later let me reason about what an attack looks like in network telemetry.
  • steganography. Data hidden in the low bits of an image, in file-format slack space, in metadata — the exercise of not trusting that a file is only what it appears to be.
  • USB forensics. Reconstructing keystrokes from captured USB HID traffic — decoding the raw interrupt packets of a keyboard back into what someone typed. Once you've done it, "the capture contains a keyboard" becomes a sentence with consequences.

$ the new kid

The most interesting recent development is a category that barely existed a few years ago: attacking AI agents with prompt injection. The challenge gives you a language-model-driven agent with a secret or a privileged action behind it, and the job is to craft input that overrides its instructions and makes it do the thing it was told not to.

This isn't a novelty. The attack surface genuinely moved — an agent that reads untrusted input and can take actions is a confused-deputy problem wearing new clothes, and the fact that it's already a CTF category means it's already an incident category somewhere in the real world. Working these challenges is how I stay honest about the fact that the definition of "the perimeter" keeps changing under everyone's feet.
