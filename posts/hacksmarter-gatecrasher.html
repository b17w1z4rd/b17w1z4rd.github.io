Hack Smarter · Easy · Blue team / DFIR

Not every box is a boot-to-root. GateCrasher is a SOC simulation: triage a queue of alerts, run the investigation, build detections, flag the right IOCs, and file an incident report. The flag drops only when the report is correct — there is nothing to cat on a filesystem. No shells, no privesc. This one is graded on judgement, and that makes it a genuinely good exercise.

The incident: a FortiGate edge appliance compromise (fgt-edge-01), launched from a TOR exit node, ending in config exfiltration and a persistence account.

$ the incident, reconstructed

Reading the timeline, the whole thing collapses to a single actor and a single host: 

source IP        185.220.101.42   (TOR exit node)
compromised host fgt-edge-01      (perimeter FortiGate)
compromised acct admin
persistence acct svc_backup
abused API path  /api/v2/cmdb/system/interface  (+ related cmdb endpoints)

The chain: credential attack against the appliance admin -> successful admin login from the TOR IP -> config export (data theft) -> a new admin account (svc_backup) created for persistence, all driven through the FortiOS REST API.

$ triage — the part that scores

The queue is mostly enterprise noise, planted to bait over-escalation. The decision rule is clean: anything sourced from 185.220.101.42 on fgt-edge-01 is the same chain; everything else is normal. Dismissed as benign:

  • MDM-pushed scheduled task
  • signed PowerShell execution
  • OneDrive sync traffic
  • certificate renewal
  • an MFA-satisfied M365 login
  • DNS to 1.1.1.1

The four malicious alerts split into Confirm vs Escalate, and that split is what the simulator grades: Confirm the failed logins and the successful admin login; Escalate the CONFIG_EXPORT and the ADMIN_USER_CREATE. Data exfiltration and persistence on a perimeter device are both above tier-1 authority.

Use “Assign to me” on the brute-force alert before you resolve it, so it doesn't age out while you pivot into the investigation.

$ investigation

One query carries the phase: 

src_ip = 185.220.101.42

Read the full timeline, not just the first hit — the report rewards listing every abused API path, and the narrative field wants the complete sequence: auth failures -> successful auth -> config export -> account creation.

$ detection engineering

Four rules give full coverage across all five attack stages. But coverage and quality aren't the same thing, and it's worth being honest about which rules you'd actually ship:

  • type == CONFIG_EXPORT — the best rule here. Zero-context, high fidelity. Config export off an edge appliance is almost never benign.
  • type == ADMIN_USER_CREATE — equally high fidelity, and arguably the most important, because account creation is the artifact that survives credential rotation. The one you least want to miss.
  • type == AUTH_FAIL — keep it, but note in the report that in production it needs a threshold and window (e.g. 5 failures / 60s / same user / same dst) or it's pure noise.
  • src_ip == 185.220.101.42 — flags full coverage, but be clear-eyed: a bare source-IP match is a blocklist entry, not a detection. Its “extra” matches are just the same IP touching unrelated events. In a real SOC you'd downgrade this to a low-severity enrichment tag and lean on the behavioral rules.

$ IOCs and report

In the IOC panel, flag the real indicators (the TOR source IP, the compromised host, the persistence account) and avoid the decoys — they penalize the score: sensor-dmz-01, internal workstation IPs, and sanctioned external destinations. Report classification that closes it out: 

incident type : edge_device_compromise
severity      : critical
verdict       : confirmed_incident

Clear the remaining pending alerts in the Alerts tab to bring the risk bar down before you submit — a lingering risk score and open alerts drag the grade. File the report, and the simulator releases the flag: 

HSM{08c9...}   # released server-side on a valid report

$ takeaway

Two things carry over to real detection work. First, an IP blocklist is not a detection — it catches this attacker's current infrastructure and nothing else; behavioral rules (CONFIG_EXPORT, ADMIN_USER_CREATE) catch the technique. Second, the highest-value alert in an intrusion is usually the persistence artifact, because it's what outlives your incident response if you miss it. Rotate every credential you like — the rogue admin account is still there.
